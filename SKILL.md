# Стартер второго мозга

Второй мозг - один файл, который агент читает в начале каждого чата: что за
проект, как человек решает, где лежат правила и чего делать нельзя. Сам файл
короткий, всё длинное лежит в папках, а в файле только адреса к ним.

Ты ведёшь человека от пустой папки (или от разросшегося CLAUDE.md) до
рабочего второго мозга: расспрашиваешь, раскладываешь ответы по папкам,
собираешь файл по скелету и проверяешь его программой.

## Три правила, которые не нарушаются

1. **Без «да» человека ничего не меняешь и не удаляешь.** Сначала
   показываешь, что сделаешь: какие файлы создашь, что перенесёшь, что
   уберёшь. Делаешь после явного «да». «Ок» на другой вопрос - не «да».
2. **Ключи, пароли, токены и данные клиентов в файлы не пишешь.** Человек
   продиктовал ключ - в файл идёт только адрес хранения: имя переменной
   окружения или файла с ключом. Самого ключа нет нигде. Имена и телефоны клиентов - тоже нет.
3. **Ответы не придумываешь.** Человек сказал «не знаю» - так и пишешь
   «пока неизвестно», пустое место не заполняешь от себя. Цифр, которых он не
   называл, в файлах нет.

## Что лежит в стартере

Пути в левой колонке - внутри папки стартера, там же, где этот файл.

| Файл | Что в нём | Куда попадёт у человека |
|---|---|---|
| `shablony/skelet.md` | скелет второго мозга из 8 разделов | основа для CLAUDE.md или AGENTS.md |
| `shablony/ai-clone.md` | заготовка «как я решаю» | `ai-clone/INDEX.md` |
| `shablony/business.md` | заготовка «что за дело» | `business/INDEX.md` |
| `shablony/goals.md` | цели и где смотреть цифры | `business/goals.md` |
| `shablony/pravilo.md` | форма файла правила | `rules/<дело>.md` |
| `shablony/plan.md` | шаблон плана большой задачи | `plans/TEMPLATE.md` |
| `prompts/pohudenie.md` | промпт похудения | `prompts/pohudenie.md` |
| `tools/check-claude-md.py` | проверка без нейросети | `tools/check-claude-md.py` |

Папка стартера после настройки человеку не нужна: что взять с собой, ты
копируешь в его проект, а стартер можно убрать (тоже после «да»).

## Как вести

- **Один вопрос - одно сообщение.** Исключение - шаг 2, там два коротких
  вопроса вместе. К вопросу можно дать 2-3 примера ответа, чтобы человеку
  было от чего оттолкнуться, но выбирает он.
- **Пиши просто**, без жаргона. Непривычное слово объясни в одну строку.
- **Прогресс - в плане.** На шаге 0 после «да» создаёшь
  `plans/ГГГГ-ММ-ДД-vtoroy-mozg.md`: короткий список шагов `[ ]`, не по
  шаблону. Отмечаешь `[x]` каждый пройденный. Человек вернулся в новом чате -
  открой этот план, скажи, на каком шаге остановились, и продолжай с первого
  неотмеченного.
- **Ответы человека записывай его словами**, без пересказа.
- **Противоречие - назови и спроси.** В ответах («цифры смотрю в таблице» и
  «таблицу не трогать» - можно ли агенту её читать) и между ответами и
  старым файлом («акция закончилась, но пусть висит» - как её подавать).
- **Одно правило - одно место.** Как работать вообще - `ai-clone/INDEX.md`;
  правило одного дела - `rules/<дело>.md`; запрет без исключений - раздел
  «Никогда» второго мозга. Одно и то же правило в двух местах не пишешь.
- Человек устал - останавливаешься после любого шага: всё уже в файлах.

## Шаг 0. План

Покажи человеку в 5-7 строк, что будет: посмотрю, что уже есть; спрошу, на
чём ты работаешь; выберу файл; задам вопросы по одному; разложу ответы по
папкам; соберу файл по скелету; проверю программой. Скажи, что займёт
примерно 30-60 минут и что можно прерваться после любого шага.

Спроси «да». После «да» создай план прогресса (см. «Как вести»).

## Шаг 1. Что уже есть

Найди и покажи списком, ничего не меняя:

- в папке проекта: `CLAUDE.md`, `AGENTS.md`, `CLAUDE.local.md`, `GEMINI.md`,
  `.cursor/rules/`, `.cursorrules`, `.github/copilot-instructions.md`,
  `.windsurfrules`, папки `rules/`, `docs/`, `notes/`, `.claude/rules/`,
  `.claude/skills/` (сам стартер не считай), `.claude/settings.json`;
- в домашней папке: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`,
  `~/.gemini/GEMINI.md`. Они грузятся во все проекты человека: покажи их и
  скажи об этом, но не трогай - настраиваем только этот проект.

По каждому найденному файлу - одна строка: сколько строк и о чём он.
Файл длиннее 200 строк - отметь: на шаге 3 его разложим, а потом пройдёт
похудение.

Ничего не нашлось - так и скажи: собираем с нуля.

## Шаг 2. На чём работает человек

Спроси одним сообщением:

- на чём ты работаешь: Claude Code, Codex, Cursor, Gemini CLI, GitHub
  Copilot, Windsurf, Hermes или что-то другое;
- один агент или несколько, и если несколько - работают ли они в одной папке
  проекта.

Если на шаге 1 нашлись файлы разных агентов - назови их, это подсказка.

## Шаг 3. Какой файл будет вторым мозгом

| Ответ | Файл |
|---|---|
| только Claude Code | `CLAUDE.md` |
| Codex, Cursor, Hermes, Windsurf | `AGENTS.md` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Gemini CLI | `GEMINI.md` |
| другой агент | посмотри в его документации, какой файл он читает при старте |
| несколько агентов в одной папке | второй мозг в `AGENTS.md`, `CLAUDE.md` - ссылка на него |

Несколько агентов:

- Mac и Linux: `CLAUDE.md` - символическая ссылка, `ln -s AGENTS.md CLAUDE.md`;
- Windows: `CLAUDE.md` из одной строки `@AGENTS.md`;
- Codex, Cursor, Hermes и Windsurf читают `AGENTS.md` сами;
- Gemini CLI - настройкой `context.fileName` на `AGENTS.md`;
- GitHub Copilot понимает `AGENTS.md` не во всех своих функциях: сверься с
  его документацией и скажи человеку об этой оговорке;
- другой агент - по его документации.

Двух разных вторых мозгов в одной папке не оставляй. Уже есть и `CLAUDE.md`,
и `AGENTS.md` с разным текстом - покажи таблицей «строка - куда переедет»,
после «да» перенеси в один файл, второй сделай ссылкой.

Был старый файл - не выбрасывай из него ничего молча: каждую строку либо
переносишь (в файл или в папку на шаге 5), либо показываешь в списке «уберу,
потому что...». Старый файл перед правкой сохрани копией рядом:
`CLAUDE.md.bak-ГГГГ-ММ-ДД`. Пароли, ключи и токены в копию не переносишь:
вместо них строка «убрано ГГГГ-ММ-ДД, хранится в ...». Скажи человеку, что
засвеченный пароль лучше сменить.

## Шаг 4. Вопросы по одному

Задавай по одному, жди ответа, записывай его словами человека. Что уже
понятно из старого файла - не спрашивай, а покажи и спроси «так?».

1. Как называется проект, что за продукт и кому ты его продаёшь?
2. Какие у тебя цели на месяц и на год, и по какой цифре поймёшь, что дошёл?
3. Где смотреть цифры: таблица, CRM, кабинет, файл? Можно ли агенту их читать?
4. Что сейчас в работе?
5. Какие отделы есть в бизнесе: кто за что отвечает, даже если везде ты сам?
6. Какие дела у тебя повторяются каждую неделю?
7. Что ты поправлял за агентом чаще всего?
8. Где агент может решать сам, а где только после твоего «да»?
9. Что нельзя делать ни при каких условиях?
10. Как ты проверяешь, что работа сделана как надо?
11. На каком языке и каким тоном тебе отвечать?

Доспрашивай одним вопросом:

- ответ короткий или непонятный;
- правило опирается на источник, которого нет в ответах: «цены только из
  прайса» - где лежит прайс. Названного файла нет на диске - в правило
  пишешь словами «прайса пока нет - цену не называть, спросить», а не
  адресом;
- повторяющееся дело из вопроса 6: что нужно на входе, чтобы агент сделал
  его сам (тема, поставщик, откуда брать отзывы).

«Не знаю» - запиши «пока неизвестно» и иди дальше.

Человек диктует ключ, пароль или токен - останови. Скажи, где его держать:
в файле `.env` в папке проекта (и `.env` в `.gitignore`) или в менеджере
паролей. В файлы второго мозга пойдёт только адрес: «токен бота - в `.env`,
переменная `BOT_TOKEN`». Имя переменной предложи сам и спроси «да».

## Шаг 5. Разложить ответы по папкам

Покажи таблицей «ответ - в какой файл ляжет» и после «да» создай файлы:

| Что | Куда |
|---|---|
| как человек работает: тон, где решает агент, что ему ценно (8, 11 и общие правки из 7) | `ai-clone/INDEX.md` по `shablony/ai-clone.md` |
| название, продукт, клиенты, отделы, что в работе (1, 4, 5) | `business/INDEX.md` по `shablony/business.md` |
| цели и где цифры (2, 3) | `business/goals.md` по `shablony/goals.md` |
| правки и правила одного дела: тексты, цены, код (7, 9) | `rules/<дело>.md` по `shablony/pravilo.md` |
| как проверить работу (10) | `rules/check.md` по `shablony/pravilo.md` |
| где лежат ключи и доступы - только адреса, если человек их назвал | `rules/security.md` по `shablony/pravilo.md` |
| шаблон большой задачи | `plans/TEMPLATE.md` из `shablony/plan.md` |
| повторяющиеся дела (6) | `prompts/<дело>.md` - промпт под каждое; чего не знаешь - строкой «спроси меня: ...» |
| программа проверки | `tools/check-claude-md.py` из стартера |
| что лежит в `tools/` | `tools/README.md`: строка на каждую программу и как её запускать |
| промпт похудения | `prompts/pohudenie.md` из стартера |

Правила:

- В сам второй мозг попадает только то, что нужно в каждом чате. Всё
  остальное - в папку, а во втором мозге адрес строкой «если сейчас такое -
  открой этот файл». Адрес пишется обычным путём в обратных кавычках, без
  знака `@`: значок `@` грузит файл целиком в каждый чат.
- Файл правила создаётся, только если человек назвал для него хоть одно
  правило. Пустых файлов-заглушек не делай.
- Повторяющаяся работа из многих шагов - предложи вынести её в отдельный
  скилл (одной строкой: «это просится в скилл, сделаем позже?»). Сам скилл
  сейчас не собирай.
- Запрет, который можно поставить замком в настройках агента, - предложи.
  Файл - просьба, настройка - замок. В Claude Code это `.claude/settings.json`:
  `permissions.deny` - нельзя никогда, даже после «да»;
  `permissions.ask` - можно, но каждый раз с подтверждением. Пример:
  удалять можно со спросом - это `ask`, а не `deny`. Внешнее (таблица в
  облаке, сообщения клиентам) настройкой не запирается - тогда только
  строка в «Никогда». Запирать нечего - так и скажи и иди дальше. Другим
  агентам - по их документации. Ставишь после «да» и показываешь, что
  именно добавил.

## Шаг 6. Собрать файл по скелету

Возьми `shablony/skelet.md` и собери из него второй мозг. Скелет - пример
чужого рабочего файла, а не текст под копирование. Файл пишется от лица
человека («мои правила», «без моей команды») и под его дело: строки про код
и сборку - только если у человека есть код, «кому продаём и почём» - только
то, что есть в его `business/`.

- `<проект>` - название из ответа 1;
- раздел 1: строки таблицы - под его задачи;
- раздел 2 «Что за проект»: первой строкой - одно предложение из ответа 1,
  что за дело и кому. Без неё агент на «привет» не поймёт, чем человек
  занимается: раздел 1 велит читать только `ai-clone/INDEX.md`;
- раздел 3: фразу про отделы оставь, если отделы есть в `business/INDEX.md`,
  иначе убери. В таблице оставь строки только тех файлов, которые реально
  созданы на шаге 5, добавь строки под его правила, под `prompts/` и под
  замок в настройках, если он поставлен;
- раздел 5 «Никогда»: строки скелета - только предложения. Покажи их
  списком и спроси одним вопросом, какие оставить. Добавь его ответы на
  вопрос 9. Строку про git оставь, только если в папке есть git;
- раздел 6: шаблон плана - `plans/TEMPLATE.md`, проверка - `rules/check.md`,
  если он создан;
- «Язык» - целиком по ответу на вопрос 11, строки скелета не оставляешь.
  Тон живёт только здесь, в `ai-clone/INDEX.md` - строка-адрес на этот
  раздел;
- адрес, которого нет на диске, в файл не пишешь.

Потолок - 150 строк, жёсткий предел - 200. Не влезает - выноси справочное
в папки.

Покажи готовый файл целиком и спроси «да». После «да» запиши его.

## Шаг 7. Проверка

1. Запусти `python3 tools/check-claude-md.py` (на Windows - `python`). Если
   Python нет, пройди те же пункты руками: адреса живы, сирот в `rules/` нет,
   дублей нет, ключей нет во всех папках второго мозга, длина в потолке.
2. Покажи строку «ИТОГ». Нашлись проблемы - покажи, как починишь, чини после
   «да» и запусти проверку ещё раз.
3. В Claude Code скажи человеку набрать `/doctor prompt-audit`: Claude найдёт
   устаревшие инструкции, адреса без файлов и противоречия и покажет их, сам
   ничего не меняя. Эта команда работает через модель и тратит лимит, поэтому
   на каждую мелкую правку хватает программы. Команда не нашлась - версия
   Claude Code старая: обнови его или пропусти этот пункт, программы хватит.
4. Попроси открыть новый чат и написать «привет»: агент должен ответить уже
   с пониманием, чем человек занимается. Не понял - смотрим, какой адрес он
   не открыл.

## Шаг 8. Похудение нового файла

Старый файл уже разобран на шаге 3. Теперь худеет новый второй мозг: на
остатки скелета, которые к делу человека не относятся, и на строки, без
которых ничего не развалится. Шаг обязателен, если старый файл был длиннее
200 строк. Потом он нужен, когда файл разрастётся или человек скажет «агент
перестал слушаться».

Открой `prompts/pohudenie.md` и пройди его: каждую строку проверяешь
вопросом «уберу - что-нибудь развалится?». Список «уберу» и «вынесу»
показываешь, удаляешь после «да».

## Финал

Покажи итог в 5 строках: какой файл стал вторым мозгом, сколько в нём
строк, какие папки появились, что показала проверка, как звать похудение.

И одно правило на будущее, скажи его своими словами: правка, которую
человек повторил второй раз, ложится в файл своего дела в `rules/`, а во
второй мозг - разве что одна строка-адрес. Тогда правил становится больше, а
файл не растёт. После каждой такой правки - `python3 tools/check-claude-md.py`.

Папка стартера и архив `starter-vtorogo-mozga-*.tar.gz` больше не нужны.
Предложи убрать их: на Mac - перетащить в Корзину, на Windows - удалить в
Проводнике. Можно и оставить, она не мешает.
Сам не удаляй.
